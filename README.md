# ML-P-3 — предобработка данных с `ColumnTransformer`

Практическая работа, вариант B.

## Что реализовано

1. Признаки разделены на числовые и категориальные.
2. Для разных групп признаков собран `ColumnTransformer`.
3. Для каждого признака выбрана и письменно обоснована стратегия заполнения пропусков.
4. Пайплайн обучается только на `train`, затем применяется к `test`.
5. Проверяется, что после преобразования `train` и `test` имеют одинаковое число столбцов.

## Данные

В репозитории находится фиксированный набор `data.csv` со следующими признаками:

| Признак | Тип | Обработка пропусков | Почему |
|---|---|---|---|
| `age` | числовой | медиана | Возраст может содержать выбросы; медиана устойчивее среднего. |
| `monthly_income` | числовой | медиана | Доход обычно имеет асимметрию и крупные значения, поэтому медиана менее чувствительна к выбросам. |
| `experience_years` | числовой | среднее | Стаж рассматривается как обычный непрерывный числовой признак; для него используется среднее значение обучающей выборки. |
| `city` | категориальный | отдельная категория `__MISSING__` | Не подменяем неизвестный город самым частым; сам факт отсутствия значения сохраняется как информация. |
| `education` | категориальный | отдельная категория `__MISSING__` | Пропуск сохраняется как отдельное состояние вместо предположения о наиболее частом образовании. |
| `employment_type` | категориальный | отдельная категория `__MISSING__` | Отсутствующий тип занятости не смешивается с существующими категориями. |

`target` — целевая переменная и в `ColumnTransformer` не передаётся.

## Пайплайн

Числовые признаки после заполнения пропусков масштабируются через `StandardScaler`.

Категориальные признаки:
- получают значение `__MISSING__` вместо пропуска;
- кодируются `OneHotEncoder`;
- используют `handle_unknown="ignore"`, поэтому новая категория в `test` не ломает преобразование.

В коде числовые признаки разделены на две подгруппы, потому что для них нужны разные стратегии заполнения:

```text
experience_years -> SimpleImputer(mean)   -> StandardScaler
age, income      -> SimpleImputer(median) -> StandardScaler
categories       -> SimpleImputer(constant) -> OneHotEncoder
```

Все эти ветки объединены одним `ColumnTransformer`.

## Проверка отсутствия утечки данных

Разбиение выполняется **до обучения предобработки**:

```python
X_train, X_test, y_train, y_test = train_test_split(...)

X_train_ready = preprocessor.fit_transform(X_train)
X_test_ready = preprocessor.transform(X_test)
```

То есть среднее, медиана, параметры масштабирования и категории `OneHotEncoder` вычисляются только по `train`. Данные `test` не используются во время `fit`.

В конце программа проверяет:

```python
assert X_train_ready.shape[1] == X_test_ready.shape[1]
```

На приложенном наборе данных получается:

```text
Исходная размерность train: (18, 6)
Исходная размерность test:  (6, 6)
После предобработки train: (18, 15)
После предобработки test:  (6, 15)
```

Следовательно, обучающая и тестовая выборки после одного и того же обученного пайплайна имеют одинаковое количество итоговых признаков.
