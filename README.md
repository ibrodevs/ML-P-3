## Выполнение задания

### 1. Разделение train и test до предобработки

Сначала выполняется train/test split, и только после этого обучается преобразователь:

```python
X_train, X_test, y_train, y_test = train_test_split(...)
X_train_ready = preprocessor.fit_transform(X_train)
X_test_ready = preprocessor.transform(X_test)
```

Это принципиально важно: параметры преобразований должны вычисляться только по тренировочным данным.

### 2. Числовые признаки

Для `age` и `monthly_income` выбрана медианная импутация. Медиана устойчивее среднего к большим значениям и выбросам.

Для `experience_years` используется среднее значение обучающей выборки.

После импутации числовые признаки масштабируются через:

```python
StandardScaler()
```

### 3. Категориальные признаки

Пропуски не заменяются наиболее частой категорией. Вместо этого сохраняется отдельное состояние:

```text
__MISSING__
```

После этого применяется:

```python
OneHotEncoder(handle_unknown="ignore")
```

`handle_unknown="ignore"` нужен, чтобы новая категория в test не приводила к ошибке.

### 4. Объединение через `ColumnTransformer`

Все ветки предобработки объединены в одном объекте:

```text
experience_years -> SimpleImputer(mean)   -> StandardScaler
age, income      -> SimpleImputer(median) -> StandardScaler
categories       -> SimpleImputer(constant) -> OneHotEncoder
```

Это делает обработку одинаковой и воспроизводимой для train, test и будущих данных.

### 5. Проверка отсутствия data leakage

`fit_transform()` используется только на тренировочной выборке. Тестовая выборка никогда не участвует в вычислении:

- средних;
- медиан;
- среднего и стандартного отклонения scaler;
- набора категорий encoder.

Поэтому информация из test не «подсказывает» модели, как именно нужно подготовить данные.

### 6. Проверка размерностей

Контрольный результат:

```text
Исходная размерность train: (18, 6)
Исходная размерность test:  (6, 6)
После предобработки train: (18, 15)
После предобработки test:  (6, 15)
```

Также выполняется проверка:

```python
assert X_train_ready.shape[1] == X_test_ready.shape[1]
```

Это подтверждает, что обе выборки после одного обученного пайплайна имеют одинаковое пространство признаков.

## Ключевые результаты

- числовые и категориальные признаки обрабатываются раздельно;
- стратегии импутации выбраны с учётом смысла признаков;
- категориальные пропуски сохраняются как отдельная категория;
- неизвестные категории test не ломают OneHotEncoder;
- обучение предобработки происходит только на train;
- train и test после преобразований имеют по **15 признаков**.

---

## Вывод

Правильная предобработка должна быть частью единого ML-пайплайна и обучаться только на тренировочной выборке. `ColumnTransformer` позволяет применять разные преобразования к разным типам признаков и гарантирует одинаковое представление данных на train и test. Такой подход предотвращает data leakage и делает дальнейшее обучение модели воспроизводимым.
